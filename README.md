# Система обліку бібліотечного фонду коледжу

Навчальний вебзастосунок для ведення електронного обліку бібліотечного фонду коледжу. Система допомагає зберігати інформацію про книги, авторів, категорії, читачів і примірники, оформлювати видачу та повернення книг і контролювати прострочені видачі.

## 1. Можливості системи

- Авторизація користувача за email і паролем.
- Створення першого облікового запису адміністратора під час першого запуску.
- Перегляд загальної статистики бібліотечного фонду.
- Додавання, перегляд, редагування та видалення книг.
- Облік авторів і категорій книг.
- Облік читачів: студентів і викладачів.
- Облік примірників та їхніх інвентарних номерів.
- Оформлення видачі книги читачеві.
- Реєстрація повернення книги.
- Автоматична зміна статусу примірника під час видачі та повернення.
- Виявлення прострочених видач.
- Пошук записів у таблицях.

## 4. Що потрібно для запуску

Перед запуском мають бути встановлені:

- Node.js і npm;
- PostgreSQL;
- будь-який редактор коду (наприклад, Visual Studio Code).

Також потрібно мати створену базу даних PostgreSQL.

## 5. Налаштування backend

Відкрийте термінал у папці `server`:

```bash
cd server
npm install
```

Створіть у папці `server` файл `.env`. У ньому мають бути параметри підключення до PostgreSQL і секрет для JWT:

```env
DATABASE_URL="postgresql://postgres:YOUR_PASSWORD@localhost:5432/library_management"
JWT_SECRET="replace-this-with-a-long-random-secret"
PORT=5000
```

Замість `YOUR_PASSWORD` вкажіть пароль свого користувача PostgreSQL. Назва бази даних у прикладі — `library_management`; якщо у вас інша назва, змініть її у рядку підключення.

**Не публікуйте файл `.env` і не передавайте іншим значення `DATABASE_URL` або `JWT_SECRET`.**

Якщо база даних ще не підготовлена, після налаштування `.env` виконайте команди Prisma, які використовувалися під час створення проєкту:

```bash
npx prisma contract emit
npx prisma db update
```

Ці команди генерують необхідні файли контракту та застосовують структуру бази даних. Якщо база вже налаштована і таблиці створені, повторно виконувати їх для звичайного запуску не потрібно.

Запуск backend у режимі розробки:

```bash
npm run dev
```

За замовчуванням сервер працює за адресою:

```text
http://localhost:5000
```

Перевірити його доступність можна за адресою:

```text
http://localhost:5000/api/health
```

## 6. Налаштування frontend

Відкрийте **другий термінал** у папці `client`:

```bash
cd client
npm install
```

У папці `client` має бути файл `.env` з адресою API:

```env
VITE_API_URL=http://localhost:5000/api
```

Запустіть frontend:

```bash
npm run dev
```

Vite виведе адресу локального вебзастосунку в терміналі. Зазвичай це:

```text
http://localhost:5173
```

Відкрийте цю адресу у браузері.

## 7. Перший вхід у систему

Під час першого відкриття застосунку, якщо в базі даних ще немає користувачів, з'явиться форма створення адміністратора.

1. Введіть ПІБ адміністратора.
2. Вкажіть email.
3. Створіть пароль довжиною щонайменше 8 символів.
4. Натисніть кнопку створення адміністратора.

Після цього можна входити до системи за вказаними email і паролем. Пароль зберігається в базі даних у вигляді хешу.

Токен авторизації зберігається у браузері, тому після перезавантаження сторінки користувач залишається авторизованим до завершення строку дії токена. Для завершення роботи натисніть **«Вийти»**.

Первинне створення адміністратора доступне лише тоді, коли таблиця користувачів порожня. Відкритої реєстрації нових користувачів у застосунку немає.

## 8. Основні розділи інтерфейсу

- **Головна** — загальна статистика бібліотеки.
- **Книги** — каталог книжкових видань.
- **Автори** — інформація про авторів.
- **Категорії** — тематичні категорії книг.
- **Читачі** — облік студентів і викладачів.
- **Примірники** — облік фізичних примірників книг та їхніх статусів.
- **Видача книг** — оформлення видачі, перегляд історії та реєстрація повернення.

## 9. Основні статуси

**Статус примірника:**
- `AVAILABLE` — доступний для видачі;
- `BORROWED` — виданий читачеві;
- `LOST` — втрачений;
- `DAMAGED` — пошкоджений.

**Статус видачі:**
- `ACTIVE` — книга видана;
- `OVERDUE` — строк повернення минув;
- `RETURNED` — книгу повернуто.

## 10. Важливо

Для роботи застосунку одночасно мають бути запущені PostgreSQL, backend і frontend.

Під час звичайного запуску відкрийте два термінали:
- у папці `server` виконайте `npm run dev`;
- у папці `client` виконайте `npm run dev`.

Якщо frontend не може отримати дані, перевірте, чи працює backend і чи правильно вказано `VITE_API_URL` у `client/.env`.

Якщо backend не може підключитися до бази даних, перевірте `DATABASE_URL` у `server/.env` та переконайтеся, що PostgreSQL запущений.
